# 轮位编号与轮系展示统一升级方案

日期：2026-10-21  
状态：用户于 2026-10-21 授权按修改后的方案实施（路线 A）。2026-10-22 用户纠正协议口径：`wheelId` 就是轮位，1～8 走行轮、9～16 驱动轮，不存在“原始轮号→显示轮位”的偏移；已按第 10 节修正。第 1～9 节保留为历史记录，其中“原始轮号 1～8＝驱动轮”的前提已作废。

## 1. 目标与实施口径

本次需求从 `qml/home/HomeWorkspace.qml` 右侧遥测区开始，但轮位编号贯穿三维选择、全景监控、查询、统计、报警、标定和周报，需要按统一规则实施。

已经明确的目标：

1. 首页走行轮卡片在上，驱动轮卡片在下。
2. 走行轮显示轮位 1～8，行名称为 `轮位1/走行轮1` 至 `轮位8/走行轮8`。
3. 驱动轮显示轮位 9～16，行名称为 `轮位9/驱动轮1` 至 `轮位16/驱动轮8`。
4. 同一个物理轮在所有页面的名称、选择、图片、测量值、判定和统计必须一致。

### 1.1 D1：下方卡片标题

原请求第 3 点指定下方驱动轮卡片名称为 **“走行轮（9～16）”**，但该卡片内的行名称为 **“驱动轮1～8”**，两者存在语义冲突。

建议确认后的标题为：

| 位置 | 物理轮系 | 建议标题 |
| :--- | :--- | :--- |
| 上方 | 走行轮 | 走行轮（1～8） |
| 下方 | 驱动轮 | 驱动轮（9～16） |

本次按用户对修改后方案的整体实施授权，采用上述建议标题；原始请求保留在上文供核对。

### 1.2 D2：仅调整显示编号，还是连 TCP/数据库编号一起调整

代码当前约定为 `wheelId 1～8＝驱动轮、9～16＝走行轮`。用户描述的界面变化有两种实现含义：

| 项目 | A：显示轮位统一调整（建议） | B：协议与存储编号全面调整 |
| :--- | :--- | :--- |
| 界面轮位 | 1～8 走行轮，9～16 驱动轮 | 1～8 走行轮，9～16 驱动轮 |
| TCP `wheelId` | 保持现行约定 | 改为 1～8 走行轮、9～16 驱动轮 |
| 已有数据库 | 原始轮号不变 | 必须迁移旧轮号并处理缓存、配置与约束 |
| 客户端 | 继续按旧协议发送 | 必须同步升级或提供明确的协议版本区分 |
| 主要代价 | 严格分离显示轮位与原始轮号 | 数据迁移、现场切换、客户端联调、回滚复杂 |

建议 A 的理由是：需求目前直接描述显示方式，尚未要求客户端改变上报编号。A 可以保留现场数据和对接方式，并满足所有页面统一显示新轮位的目标。**本次已按用户整体授权采用路线 A。** 如果现场希望 TCP 的 `wheelId` 也就是新的物理轮位，应采用 B，不能只改显示层。

两种路线必须二选一，不能在部分页面使用 A、其他页面使用 B。

## 3. 统一术语与完整映射

为避免同一个整数在不同地方含义变化，代码与文档应区分：

- **原始轮号 `rawWheelId`**：TCP `wheelId`、数据库 `wheel_id`、既有查询键。
- **显示轮位 `positionNo`**：现场界面统一显示的新轮位 1～16。
- **轮系内序号 `typeIndex`**：走行轮或驱动轮各自的 1～8。
- **轮类别 `wheelType`**：走行或驱动，不由显示顺序决定。
- **相机号 `cameraId`**：1～12，独立于轮位；`slot` 必须按实际来源判断语义。

## 4. 路线 A 的实施设计（本次采用）

### 4.1 单一映射入口

建议增加 `src/common/WheelIdentity.h/.cpp`，集中提供原始轮号与显示轮位的双向转换、轮系内序号、类别、统一行名称及显示排序。实际文件拆分可按实现复杂度精简。

通过 `AppController` 暴露必要的轻量转换给 QML，避免每个页面自行编写 `+8/-8` 或依靠文案解析。新源文件登记到 `CMakeLists.txt` 的程序与相应测试目标；QML 只消费该映射，不另立第二套规则。

接口约束：

1. 原始数据对象中的 `wheel`/`wheelId` 继续表示原始轮号；不能原地替换为显示轮位后再提交查询。
2. QML 使用明确命名的 `positionNo`、`typeIndex`、`displayLabel` 等派生属性；若服务层需要新增这些字段，保留原有字段并验证兼容。
3. 查询、图片读取、统计下钻、标定保存全部传原始轮号。
4. 面向操作员的数字轮位输入统一解释为显示轮位，在提交查询前转换一次；`DRIVE`/`WALK` 继续表示物理轮系，含义不变。
5. 不在每层重复转换。以 `QueryConditionBar` 输出原始筛选键为例，数据页收到后直接调用后端，不再次转换；明确记录接口契约。
6. 非法编号、空值、未选中状态不能映射成有效轮；显示占位、查询拒绝或清空选择，不默认落到轮位1。
7. 跨页跳转链路 `openGenericSearch` → `MainFrame` → `openGenericQuery` → `applyQuery` → `setSelectionToken` 全程只传原始轮号，转换只发生在发起方（如速查解析用户输入时）。`0` 固定表示“不筛选轮位”，`setSelectionToken` 收到 0 或非法值时应落到“全部/不筛选”而不是 `DRIVE`；若现有查询栏没有“全部”选项，需先补上，不能沿用回退到驱动轮整组的行为。

### 4.2 首页卡片和三维联动

1. 上方使用 `effectiveWalkingWheels`，下方使用 `effectiveDriveWheels`，卡片标题按 D1 确认结果设置。
2. 各行用统一名称；数据源、判定、合格率仍随原始轮号绑定。
3. 无数据时保持 8 行占位和未检测状态，使用同一映射生成名称，不补造有效检测值。
4. `selectedWheel` 明确保留原始轮号；行点击、再次点击取消、三维反向选中都维持同一身份。
5. 三维标签的内部键可继续使用“走行轮1”等物理名称；可见详情补充新轮位。已有 `wheelId` 字样如需保留，必须明确为协议编号。
6. `openLatestImage` 仍传原始轮号，预览标题使用新名称。不能把显示轮位1直接当原始轮号1查询。
7. 不改变模型节点、物理位置、相机标记和12宫格排序；两次触发只更新本批相机的原有行为必须保留。
8. 12 宫格卡片和图像检验对话框显示的 `wheelsInfo` 说明串必须与遥测区行名称一致。建议 `IngestCoordinator` 继续只产出原始轮号，由 QML 侧按映射渲染；若选择在 C++ 侧拼新名称，须保留原始轮号字段供查询，并同步更新 `tests/CoreBoundaryTests.cpp` 中对该串的断言，不能只改文案让测试通过。检验对话框“检测轮号”在 `wheelId` 缺失时不得用 `slot`（相机槽位）冒充轮号，应显示占位。

### 4.3 全景、历史查询和报警记录

1. 全景行按走行1～8、驱动1～8排列；行数据保留原始查询键，并用新轮位显示行头。
2. 全景较窄的行头可分两行显示“轮位1 / 走行轮1”，悬浮提示提供完整名称；不能通过缩小中文至 `fontMicro` 解决拥挤。
3. 通用选择器将走行分组放在前，按钮显示新轮位，提交原始轮号；整组选择与单轮选择得到相同集合。
4. 历史/报警表格、缩略图标签、全屏预览和记录详情统一显示新轮位与物理轮名称，检查必要的列宽。
5. 快速搜索“轮位1”转换到原始9，“驱动轮1”转换到原始1；裸数字沿用已有架号候选，但轮位候选按新轮位解释，标题明确类型，避免模糊跳转。
6. `slot` 若表示相机工位，不做轮位转换；只有确认实际为 `wheelId` 别名的路径才能应用轮位映射。实施时进一步核实：`SearchService`/标定查询的 C++ 结构曾赋 `slot = wheelId`，但 `ImageListModel::data/get` 暴露给 QML 的 `slot` 始终取相机号。因此所有 QML 轮位展示、标定列定位和轮位预览必须使用 `wheelId`，不得回退或转换 `slot`。
7. 热力图像页每个相机格子的轮说明串（`SearchService::latestRoundImages` 拼出的 `轮%1 %2 %3mm`）按与 4.2.8 相同的方式处理：后端保留原始轮号，显示层统一用新名称，一张图带多轮时逐条转换。

### 4.4 统计和报警分析

1. 保留驱动/走行分组的真实数据范围、`wheelType` 枚举与后端统计键；统一修改面向用户的轮位范围说明。
2. 统计图若横轴表示轮位，则驱动显示9～16、走行显示1～8；若保留轮系内1～8，轴标题必须明确写“驱动轮序号”或“走行轮序号”。
3. 图表点击、表格选中和图片下钻继续传原始轮号；不能根据图表上的显示文本直接查询。
4. 同步更新 `RackWheelStats.displayWheel` 等已有转换，防止重复偏移；保留当前日期、架号和判定筛选含义。
5. 统计数量、合格率、损耗率、NG 次数以及异常证据链的实际记录集合在升级前后保持一致。
6. 整组选择的默认类别继续沿用页面现状；本次仅统一轮位规则，不额外改变页面默认业务行为。

### 4.6 CSV、周报与日志

## 5. 如果选择路线 B：额外必做工作

路线 B 的目标是“客户端、数据库、界面都使用新轮位”。必须另行落实以下切换设计，并在实施前补齐现场信息。

1. **确认旧数据真实性**：当前代码只能证明服务端如何解释编号，不能证明现场客户端一直按此约定发送。先用客户端配置、物理轮图片和旧库样本交叉核对，不能仅依据数值范围批量交换。
2. **明确旧新版本边界**：旧号与新号范围都是1～16，无法靠报文值自动识别。采用停机后客户端/服务端同步切换，或明确的协议版本字段及过渡策略。没有版本标识时不得让两种编号客户端同时写入。
3. **迁移范围**：至少包括 `record`、`alertrecord`、`carrier_wheel_status`、`carrier_wheel_norm` 的轮号，以及 `DbSchema` 中旧配置迁移逻辑；旧的驱动轮配置须落到新9～16，不能只迁移检测记录。
4. **迁移算法**：在 `DbSchema` 中增加可追踪的迁移版本/标记；整库备份后单事务迁移。唯一键表采用临时表重建或经过约束审查的中间映射，不能直接逐行交换主键。记录表更新与缓存/报警触发器必须协调，避免更新过程污染衍生表。
5. **核对与幂等**：迁移前后按载具和物理轮对比行数、OK/NG分布、图片引用、标准间距/公差；迁移标记与数据同事务提交。故障回滚、重启重试、二次启动均不得再交换一次。
6. **全链路改号**：统计/查询分组改为走行1～8、驱动9～16；首页数据分组、三维双向映射、标定读写和周报分组一并调整。不能沿用路线 A 的二次显示转换。
7. **幂等与在途请求**：清空或完成客户端待重发队列，核实请求去重存储与新旧版本关系；`requestId` 继续可选。不能为切换而清空业务记录或无条件绕过去重。
8. **历史报表**：现存 CSV 仍保留旧编号；明确其生成版本，不覆盖旧文件；新生成报表注明新编号口径。
9. **部署与回滚**：先停止旧客户端写入并关闭程序，备份整个程序和数据目录，再启动新程序迁移并切换客户端。失败时恢复备份并回退双方版本；升级后已接收的新数据需要独立保留和处理，不能简单让旧程序读取已迁移的新库。
10. **额外输入**：需要确认现场客户端能否配合、当前真实轮号定义、是否存在混用编号的旧库，以及旧 CSV 的下游使用情况。未明确前不执行数据库编号迁移。

## 10. 口径修正（2026-10-22）

用户核对首页卡片后指出：发送 `wheelId: 1` 显示“轮位9/驱动轮1”是错的。`wheelId` 本身就是轮位，轮位 1 是走行轮1。即客户端上报编号与界面轮位相同，第 1.2 节 D2 中“代码当前约定 1～8＝驱动轮”只是服务端旧的误读，不是现场协议。

修正后的规则（唯一口径）：

| `wheelId` / `wheel_id` / 轮位 | 轮系 | 轮系内序号 | 界面名称 |
| :--- | :--- | :--- | :--- |
| 1～8 | 走行轮 | 1～8 | 轮位N/走行轮N |
| 9～16 | 驱动轮 | 1～8 | 轮位N/驱动轮(N-8) |

实施内容：

- `WheelIdentity`：`position`/`rawId` 改为恒等，不再 ±8；`typeName`/`csvIdentity` 按 1～8 走行、9～16 驱动判定。接口名保留，所有 QML/C++ 调用点无需改签名。
- 后端分组全部翻转：`SearchService` 的 `DRIVE`→9～16、`WALK`→1～8；`StatsService::homepageCurrentDetection` 走行填 1～8、驱动填 9～16；`rackWheelResultStats` 的 `wheelType=0`（驱动）起点改为 9；`driveWheelRackStats`/`walkingWheelRackStats` 范围互换；周报驱动文件取 9～16、走行文件取 1～8。
- 标定对象仍是 8 个驱动轮，但轮位为 9～16：`AppController` 标定查询与分页改为 `wheel_id BETWEEN 9 AND 16`；`SettingsStore` 标准间距按轮位 9～16 读写（数组下标 0..7 仍对应驱动轮 1..8）；`DbSchema` 旧 `agcRackWheelNorm.json` 的 `wheelno` 1～8 迁移到轮位 9～16；标定页列头与图片按 `wheelId - 9` 定位。
- QML：首页占位走行 1～8、驱动 9～16；三维驱动轮标签取 `wheelLabel(9..16)`、走行轮取 `wheelLabel(1..8)`；全景行 `isDrive = 轮位 ≥ 9`；架号/轮位/报警统计页的轮系令牌、偏移和直方图索引全部互换。
- 测试：身份映射、CSV 身份列、标定键、周报分组、统计分组、卡片与热力图像说明串、QML 标定定位用例全部改为新口径。
- README：`wheelId` 说明和映射表改为“轮位即编号”，示例改为 `wheelId: 1` → 轮位1/走行轮1。

不需要数据迁移：数据库 `wheel_id` 一直存的就是客户端上报的轮位，只是服务端以前把 1～8 解释成驱动轮。联调库每轮测试前清空，不存在旧解释遗留的配置数据；现场若已有按旧解释保存的驱动轮标准间距（轮位 1～8 行），需要手工核对后重新标定一次。
